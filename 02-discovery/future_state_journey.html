From stuck at the income request to a plan Mara can keep

Mara: shift worker, two open claims, stable but variable income. She wants to settle both with an affordable plan, in a few spare minutes on her phone.

  2. 2Size Gaining control

Confidence starts lowConfidence builds with every explained stepPlan agreed, no call needed

  1. Orient

    User action

    • Opens one link on her phone→sees both claims and the total together.
    • Sees a plan preview before any form→knows what she's agreeing to.

    Internal state

    WarytoOriented

    Pain point addressed

    Not knowing whether both claims can be handled together.

  2. Size

    User action

    • Enters a typical shift-pay range, not exact figures→gets a realistic monthly amount.
    • Reads a short "why we ask" beside each question→trusts the request and continues.
    • Slides the amount up or down→sees payoff date and cost instantly.

    Internal state

    LosttoIn control

    Pain point addressed

    Why the portal asks for income, and whether the plan is affordable.

  3. Verify

    User action

    • Uploads only required documents, with a quality check→avoids rejections and repeat uploads.
    • Saves progress and resumes later→never loses her place between shifts.

    Internal state

    GuardedtoAt ease

    Pain point addressed

    Hunting for documents, then giving up and calling an agent.

  4. Commit

    User action

    • Reads plain-language missed-payment rules→accepts knowing exactly what happens if she's late.
    • Confirms both claims in one plan→settles everything in a single sitting.
    • Taps "talk to an agent" if stuck→Daniel gets full case context, no repeat questions.

    Internal state

    FearfultoSecure

    Pain point addressed

    Fear of consequences, and agents re-running checks from scratch.

Three competitive advantages over the manual workaround

  1. Affordability is built inShe no longer needs her bank app, calculator or notes to find a monthly figure, so she doesn't abandon at the income request.
  2. Every ask is explained"Why we ask" and missed-payment rules replace the FAQ detour, so she doesn't call an agent just to get answers.
  3. Handoffs carry contextDaniel picks up where she stopped, with both claims in view, instead of re-running checks one claim at a time.

Assumptions to validate: bank app, calculator, document hunt and camera upload as current workarounds; income-range entry and optional document upload are design hypotheses.
